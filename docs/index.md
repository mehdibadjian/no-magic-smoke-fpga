# AMD UltraFast Design Methodology: The Brain-Friendly Guide

Welcome to the brain-friendly companion to the AMD UltraFast Design Methodology. This guide teaches FPGA engineering the way Head First teaches anything: an analogy gets you in the door, and then you do the arithmetic, read the report, write the constraint, and check your answer.

**The analogy is the on-ramp, never the destination.** Every metaphor in this book is mapped, in the same section, onto named silicon (`BUFGCE`, `DSP48E2`, `RAMB36E2`, Laguna registers), named tool commands (`report_cdc`, `report_control_sets`, `report_qor_suggestions`), and numbers with units. If you can enjoy a section without learning something you can type, that section has a bug — see [AUTHORING.md](https://github.com/mehdibadjian/no-magic-smoke-fpga/blob/main/AUTHORING.md).

## What's Inside?

This guide covers everything from initial board planning to final system-level tuning:

*   **Chapter 1: Board and Device Planning** - Setting the foundation for success.
*   **Chapter 2: Design Constraints and Analysis** - Navigating the timing and CDC minefields.
*   **Chapter 3: Design Creation** - RTL coding, IP integration, and security.
*   **Chapter 4: Design Implementation** - Synthesis, placement, and closing the loop.
*   **Chapter 5: Power and Thermal Management** - Keeping your silicon cool and efficient.
*   **Chapter 6: Debug and System Validation** - Using the digital stethoscope and winning the race.

## How to use this guide?

Navigate through the chapters using the sidebar. Every section carries the same eight blocks, in the same order, so you always know where to look:

| Block | What it is for |
| --- | --- |
| **Fireside Chat** | Dialogue between two concepts, to make the tension between them concrete. |
| **Brain Power** | A question posed mid-section. Every one of them is answered later in the same section. |
| **Analogy → Silicon** | The mapping table: each metaphor, the real construct it stands for, and **where the analogy stops being true**. |
| **Do the Math** | A fully worked calculation — formula, substitution, units, and a verdict. Slack budgets, MTBF, PDN impedance, BRAM sizing, configuration time, Little's Law. |
| **The Real Artifact** | Something complete you can paste into a project: a full XDC file, a synthesizable module, a Tcl procedure, or an annotated tool report. |
| **Code Detective** | Spot the flaw — and then read the corrected code, not just the diagnosis. |
| **Sharpen Your Pencil** | Exercises you do with a datasheet and a calculator. No lab hardware required. |
| **Answers** | Full working for every question the section asked. |
| **There Are No Dumb Questions** | The technical "wait, but what about…" questions the prose glossed over. |
| **Bullet Points** | The reference card: commands, attributes, thresholds and formulas, scannable a year later. |

Worked examples state their givens. Device-specific figures name the family and speed
grade, and anything that varies by device or tool version is presented as an assumption
for the arithmetic rather than as a constant — because the calculation is the lesson, not
the constant.
